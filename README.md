# Jianpu

[English](README.en.md) | 简体中文

一个正在开发中的 Typst 简谱排版包，包名和公开排版命令均为 `jianpu`。

内部实现按职责拆分：`parser.typ` 解析输入，`geometry.typ` 提供全局尺寸，`glyphs.typ` 绘制局部记谱图元，`links.typ` 处理横向坐标与连线，`layout.typ` 负责小节、行和 track 渲染，`title.typ` 提供曲谱标题布局。`jianpu.typ` 只保留公开入口。

## 为什么
目前并没有一个完美的开源简谱编排软件。最接近理想状态的应该是jianpu-ly，我也有部分参与。众所周知，lilypond是一个优秀的乐谱编排工具，五线谱非常精美，可以跟专业软件掰手腕；然而天然不支持简谱，其排版底层逻辑也似乎天然与简谱不太兼容；也众所不周知，lilypond扩展所用的语言为Scheme，一个看一眼就劝退的语言，彻底打消了我写lilypond扩展的想法。jianpu-ly基本没有用到lilypond的扩展，而是用python套了一层壳，以及一系列奇技淫巧达成了排版简谱的目的，不得不说也算是成功；但这种绕弯实现目的的方案，意味着各种微调和版本不兼容，目前jianpu-ly已经面临如此困境。

另外还有重要的一点，我的最终目的是在简谱基础上再加功能，其中一个就是可能出现大段的文字。lilypond完全不是个文字排版软件，其对中文的支持程度仅限于能正常显示汉字。我们当然可以用LaTeX + lilypond来解决问题，但又该如何兼容jianpu-ly呢？

于是我动了用现有的文字排版软件来做一个简谱排版的念头，而此时我看到了Typst。虽然我也不懂Rust，但是显然相对于也基本无法看懂的TeX语言，Typst的代码还是好懂太多了，况且还能实时编译。（听说LuaLaTeX的实时编译已经近在眼前了，或许后续再用LaTeX来做一个也犹未可知呢。）

当然我还是不懂Rust，但是我们有Codex。

至于还是想五线谱和简谱混排、想输出midi、想自动检查时值错误等等额外功能的，jianpu-ly依然是为数不多的选择。现在网上也越来越多免费的简谱编辑平台了，可喜可贺。

## 使用方式

从 Typst Universe 导入：

```typst
#import "@preview/jianpu:0.1.0": jianpu, jianpu-inline, jianpu-title

#jianpu(```melody
1 2 3 4 | 5/ 6/ 7/ 1/ |
```)
```

直接克隆仓库进行本地开发时，可将导入行临时改为：

```typst
#import "jianpu.typ": jianpu, jianpu-inline, jianpu-title
```

曲谱标题可以包含居中的标题、副标题，以及左右两块信息区：

```typst
#jianpu-title(
  [曲目标题],
  subtitle: [曲目副标题],
  key: "1=G",
  meter: "4/4",
  authors: (
    (name: [张三], role: [作词]),
    (name: [李四], role: [作曲]),
  ),
)
```

`key`、`meter` 分别表示调式和节拍，均使用固定格式的字符串并以粗体排印。调式写作 `key: "1=G"`；升降调按简谱惯例把变音记号写在音名前，例如 `key: "1=#F"`、`key: "1=bB"`，排版为 `1=♯F`、`1=♭B`。后置输入 `"1=F#"`、`"1=Bb"` 也会被兼容并规范为前置形式。调式数字使用 Arial Bold，等号和调名字母使用粗体衬线字体，升降号使用 Bravura Text；节拍使用 `"分子/分母"` 格式，例如 `meter: "2/4"`，函数内部会将其排成完整行高的粗体显示型数学分数。`authors` 按顺序接收带 `name`、`role` 字段的作者信息。不需要的副标题、调式、节拍或作者可以省略。标题字号为当前字号的 `1.5em`，副标题继承当前字号，字体则继承调用位置。

行内简谱使用普通字符串：

```typst
正文中的 #jianpu-inline("1 2/ 3//. 4'") 会继承当前文字字号。
```

`jianpu-inline` 始终使用最小音符与小节间距，整体作为一个不可自动换行的行内盒；它不会自动补终止小节线，只有字符串中显式写出的 `|` 才会绘制普通小节线。

传入 `compact: true` 可启用紧凑模式。此时四分、八分、十六分和三十二分音符使用相同的最短基础盒宽，时值线仍照常绘制；附点和倚音仍会保留自身必需的额外空间。

当前公开接口：

- `..groups`：一组或多组 raw 简谱代码。
- `font`：字体，默认 `Arial`。
- `size`：字号，默认 `12pt`。
- `sort-chords`：和弦是否按相对音高由低到高排列，默认开启。
- `justify-last`：是否对齐最后一行，默认关闭；其余各行始终两端对齐。
- `first-indent`：首行缩进，默认 `24pt`。
- `lyrics-font`：歌词字体；默认 `none`，即继承调用位置的正文字体。

`jianpu-inline` 提供 `font`、`sort-chords` 和 `compact` 可选参数；字号自动继承调用位置的文字字号，`compact` 默认关闭。

简谱数字默认使用 `Arial`，变音记号和附着音乐符号使用 `Bravura Text`。这两种字体不会随 Universe 包分发，使用前需确保 Typst 能发现它们；本地既可以安装字体，也可以在编译时通过 `--font-path` 指定字体目录。也可以通过 `font` 参数替换数字字体。

raw 的语言标记用于声明 track 类型。`lyrics` 会附着到它前面最近的一条 `melody`，并与旋律使用相同的换行和音符中心坐标。

```typst
#jianpu(
  ```melody
  1 2 3 4 | 5 6 7 1 |
  ```,
  ```lyrics
  春眠 不 觉 晓 | _ 处 闻 啼 鸟 |
  ```,
)
```

## 当前记谱规则

组合与结构指令同时接受简写和全称：`c`/`chord`、`g`/`grace`、`t`/`tuplet`、`r`/`repeat`、`a`/`alter`、`h`/`harmonic`。两种写法只在词法入口不同，生成的乐谱模型完全相同。

- `1` 表示四分音符宽度的音符。
- `1/` 表示八分音符，并绘制一条时值线。
- `1//` 表示十六分音符，并绘制两条时值线。
- `1///` 表示三十二分音符，并绘制三条时值线。
- 连续时值线按四分音符为一组；累计达到一个四分音符后，即使后续仍是短音也会断开重组。
- `sym.harmonic` 紧跟在音符后，使用标准空心圆泛音记号，例如 `1' sym.harmonic`；和弦与倚音内部也可逐音书写，例如 `c[1 sym.harmonic 3 5]`、`g[6 sym.harmonic 7]`。符号本身决定放置方向。
- `1^"dolce cantabile"`、`1_"轻声"` 分别在音符上方和下方放置正文文字；也可与音符分开书写为 `1 ^"dolce cantabile"`。文字左缘与数字左缘对齐并向右自然延伸，但不改变乐谱本身的小节分行和疏密。文字到达行末且后面已有乐谱行时，续文从下一行乐谱左侧继续；只有当前是最后一行乐谱时，才在原位置按剩余宽度折行。只有与各段文字实际横向范围相交的音符、八度点、连线等障碍参与避让。
- `1^[*dolce* #text(fill: red)[cantabile]]`、`1_[#text(style: "italic")[轻声]]` 使用 Typst markup 富文本标注。方括号支持嵌套，内部字符串通过 `eval(..., mode: "markup")` 求值；由于任意 content 无法安全拆回带样式的源码片段，富文本越过行末时使用当前行的本地段落折行，不参与纯文本标注的跨乐谱行续排。
- `h{ ... }` 或 `harmonic{ ... }` 为范围内所有 `1–7` 普通音符、和弦成员和倚音成员自动添加泛音，例如 `harmonic{ 1 2 | chord[1 3 5] 6 | }`；`0`、`X` 和延长横线 `-` 不添加。作用域不建立小节边界，也可只包围小节中的一部分。
- `1.`、`1/.`、`1//.` 表示附点音符；附点在音符后方增加原时值盒一半的宽度，但始终以固定间距贴近数字，不会扩大数字前方的空间。
- `#1`、`b2`、`n3` 分别表示升、降、还原；`x4`（或 `##4`）和 `bb5` 表示重升、重降。变音记号只增加主音符前方的空间，不改变数字、上下八度点、附点、时值线和连线锚点的位置。
- `t3[1 2 3]/` 或 `tuplet3[1 2 3]/` 表示三个等时值八分音符组成的三连音，组后的时值后缀统一作用于全部成员；`t5[1 2 3 4 5]//` 等写法同理。若成员时值不同，则省略组后缀并分别书写，例如 `t3[1/ 2// 3// 4/]`、`t3[1 2/]`。组后缀与成员时值不可混用。
- 连音组只记录排版范围和显示数字，不计算实际演奏时长；当前不可跨小节，也暂不支持连音组嵌套。成员可以带变音号、八度点、附点和连线，也可以是和弦或倚音。
- `c[1 3 5]/` 或 `chord[1 3 5]/` 表示和弦；括号内音符从下往上堆叠，括号后的时值属性作用于整个和弦。
- `g[6 7] 1` 或 `grace[6 7] 1` 表示前倚音，`1 g<[2 3]` 或 `1 grace<[2 3]` 表示后倚音。
- 倚音与主音可以隔着小节线书写，例如 `g[6 7] | 1`；装饰弧线会穿过小节线，表示时值取自上一小节末尾。
- 圆括号可以写在倚音成员上，例如 `g[6( 7] 1)`、`1( g<[2 3)]`；也支持从中间成员开始或结束。
- `1( 2 3 4)` 表示连奏线（圆滑线），从 `1` 连到 `4`。
- `1~ 1` 表示延音线，连接当前音符与后一个音符。
- 连线符号可以紧贴音符，也可以独立留空格，例如 `1 ( 2 3 4 )` 和 `1 ~ 1`。
- `r{ ... }`/`repeat{ ... }` 表示默认演奏两遍的反复段，`r3{ ... }`/`repeat3{ ... }` 表示总共演奏三遍；三遍及以上会在结束反复线上方标出 `×3` 等次数。
- 连续反复位于同一行时合并为双向反复线；如果恰好在该边界换行，则上一行绘制结束反复线，下一行重新绘制开始反复线。
- `a1{ ... }`/`alter1{ ... }`、`a2{ ... }`/`alter2{ ... }` 表示不同结尾，必须写在所属的反复块内；共用结尾既可列举为 `a1,2,3{ ... }`，也可简写为范围形式 `a1-3{ ... }`。排版时只合并三个及以上的连续次数，每个编号统一带点，并以空格代替输入中的逗号，例如 `a1,2,4,5,6` 显示为 `1. 2. 4.–6.`。
- `r` 和 `a` 的大括号边界天然与小节线对齐，因此大括号前后的 `|` 均可写可不写；相邻的显式 `|` 只作冗余确认，不会生成空小节。
- 方括号用于和弦、倚音等局部音符组合，大括号用于反复和结尾等跨小节结构。当前暂不支持嵌套反复。
- `-` 表示延音占位，显示为居中的自绘横线。
- `|` 表示小节线，也是唯一允许自动换行的位置。
- 每段旋律末尾自动绘制左细右粗的终止小节线；源码最后的 `|` 可以省略。

连奏线和延音线可以跨小节与换行；行末、行首会自动绘制为相接的开放弧线片段。

不同结尾上方使用衬线字体编号。除最后一个结尾外，结尾范围线默认在右端闭合；最后结尾继续进入后续音乐时保持开放，结束全曲时闭合。范围线跨行时只切成开放的续接片段，不在人工换行处增加竖钩或重复编号。

当前支持的 raw 类型：

- ` ```melody`：旋律。
- ` ```jianpu`：兼容旧写法，按旋律处理。
- ` ```lyrics`：歌词；同一条旋律后可以连续放置多行歌词。

歌词默认继承调用位置的正文字体，不使用简谱数字的 `font` 参数；也可以通过 `lyrics-font` 单独指定。歌词以空白分隔音符位置，中英文规则相同。没有空格的内容作为整体与一个音符居中；ASCII 连字符还会拆分英文音节，并在相邻音节之间显示连字符；下划线 `_` 消耗一个音符位置但不显示文字。小节线 `|` 只用于提高源码可读性，不消耗歌词位置。歌词的实际盒宽参与最小行宽计算：普通词组之间至少保留一个西文空格，连字符音节之间为连字符本身留出空间；`_` 不建立文字盒，因此前后歌词可以自然利用空音符提供的距离。

## 开发

仓库中的示例和测试使用相对路径导入，以便直接检验当前工作区源码；面向使用者的代码应使用 `@preview/jianpu:0.1.0`。

编译视觉测试：

```console
typst compile --root . tests/visual.typ tests/visual.pdf
```

编译示例：

```console
typst compile --root . examples/basic.typ examples/basic.pdf
typst compile --root . examples/beams.typ examples/beams.pdf
```
