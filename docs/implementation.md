# 实现说明

本文记录当前 `jianpu.typ` 的核心实现方式，方便后续继续开发时理解现状。

## 模块结构

- `src/parser.typ`：raw 分词、音符属性和 score 数据模型。
- `src/geometry.typ`：由字号推导的全局私有尺寸。
- `src/glyphs.typ`：数字头、和弦、倚音、圆点及其他局部图元。
- `src/links.typ`：横向系统几何、连线锚点、跨行片段、曲线和避让。
- `src/layout.typ`：小节各绘制层、整行分配和 track 渲染。
- `src/title.typ`：标题、副标题与左右曲谱信息区。
- `jianpu.typ`：公开参数、输入解析和模块编排。

依赖保持单向：`geometry` 不依赖其他模块，图元只依赖几何，连线只依赖图元，布局组合图元与连线，公开入口最后调用布局。主音与倚音共同使用 `note-layer-metrics` 推导圆点、时值线和层间距，并共同使用 `octave-dot-slot` 完成定高的上下点对齐。二者只在垂直图元和尺寸模型上复用；主音的整行时值线分组与倚音的组内缩放、抬升仍由各自布局器负责，避免把不同横向语义塞进同一个函数。

公开入口包含三种：`jianpu` 负责可分行的块级简谱，`jianpu-inline` 接受普通字符串并在 `context` 中读取当前位置的 `text.size`，`jianpu-title` 负责曲谱标题和元信息。标题模块整体继承当前文字环境；主标题为 `1.5em`，副标题为 `1em`。公开参数 `key`、`meter` 自动排在左侧，结构化的 `authors` 列表自动排在右侧，每项作者由 `name` 和 `role` 组成。`key` 接受 `"音级=调名"` 字符串，规范输入把升降号置于音名前，如 `"1=#F"`、`"1=bB"`；后置 ASCII 写法也会解析并统一为简谱常用的 `1=♯F`、`1=♭B`。音级用 Arial Bold 绘制，等号和调名用 New Computer Modern 粗体衬线字体绘制，变音记号取 Bravura Text 字形。`meter` 接受 `"分子/分母"` 字符串，内部拆分为正整数并使用 `math.equation(block: true)` 与数学粗体绘制完整行高的分数，再用私有宽度盒限制其横向占位。

行内入口把全部小节交给同一个 `render-row`，以 `row-min-width` 作为盒宽并关闭分散对齐，因此不会换行且只使用最小间距。解析时同时关闭自动终止线；显式 `|` 仍作为普通小节线保留。行内入口还可传入 `compact: true`：解析器此时仍保留斜线所表达的时值及绘制层级，但把普通音符和和弦的基础时值宽度统一为 `short-width`；附点追加宽度和倚音组的可见宽度下限继续参与占位。

行内盒的基线不是盒底，而是主音数字行的文字基线。渲染前会计算主音行下方实际存在的时值线层、层间距及下八度点预留，并把盒基线从底部上移相同距离。这样无论简谱是否带时值线或下点，主音数字都与段落中的普通文字共享基线。

## 输入与 track

`jianpu` 接收一组或多组 raw 代码块：

```typst
#jianpu(
  ```melody
  1 2 3 4 | 5/ 6/ 7/ 1/ |
  ```,
)
```

raw 的语言标记用于区分 track 类型：

- `melody`：旋律，当前会渲染。
- `jianpu`：兼容旧写法，按旋律处理。
- `lyrics`：歌词，占位保留，当前不渲染。

内部先将 raw group 解析为 track，再组成 score：

```text
score
  tracks[]
    kind
    source
    measures[]
```

当前只渲染 `kind == "melody"` 的 track。多 track 目前是顺序渲染，尚未做跨 track 的 system-level 对齐。

## 音符解析

除 `|` 以外，每个 token 都会被解析为一个音符事件。当前 `0`、`X` 也算音符事件。

音符对象主要字段：

```text
note
  raw             原始 token
  beams           "/" 数量
  pitch           音级
  octave          八度偏移
  relative-pitch  相对音高，用于后续排序
  octave-up       "'" 数量
  octave-down     "," 数量
  accidental      变音记号
  dots            附点数量
  leading-width   变音记号前置占位
  min-width       最小宽度
  trailing-width  附点后置占位
  tuplet          所属连音组的编号、组内序号和成员数
```

解析器先移除变音前缀，再把音高数字作为主字形，其余后缀作为属性处理。`-` 例外：它仍可按当前模型参与音符事件布局，但显示时不使用字体默认减号，而是绘制一条居中的横线，避免默认字形过短、位置偏低。

## 最小宽度

音符最小宽度由时值决定：

```text
1      四分音符，2em
1/     八分音符，1.5em
1//    十六分音符，1em
1///   三十二分音符，1em
```

实际实现中这些值都由 `size` 推导为绝对长度：

```text
quarter-width = size * 2
eighth-width  = size * 1.5
short-width   = size
```

附点是音符属性，不直接混入数字字形。每个附点使音符最小宽度增加其原始时值宽度的一半：

```text
dotted-width = base-duration-width * (1 + dots * 0.5)
```

数字仍位于未附点的基础时值盒中心；附点增加的占位宽度只追加在事件右侧，不会反向扩大数字前方的空间。解析结果将基础盒记录为 `min-width`，将附点新增空间单独记录为 `trailing-width`；音符、上下八度点和时值线层都会在基础盒之后插入同一个空列。连线坐标累计两段宽度，但锚点仍取基础盒中心。附点根据数字实际字形宽度放在其右侧，使用固定的相对间距，并位于数字高度中心略偏下。因此改变时值只改变占位宽度，不会改变附点与数字之间的视觉距离。

变音记号使用 `#`、`b`、`n`、`x`/`##`、`bb` 前缀解析，字形取自 Bravura Text 的 SMuFL 标准码位。它与附点采用方向相反但结构相同的占位方式：`leading-width` 是基础盒之前的独立空列，字形由主音盒向左越界绘制。`event-width` 包含前置列、基础盒和后置列，而 `event-head-offset` 指向 `leading-width + min-width / 2`。音符行、上下点行、时值线行和连线坐标统一使用这两个函数，因此变音记号参与分行，却不会移动任何主音附属标记。和弦取成员前置宽度的最大值；倚音成员宽度、组宽、时值线端点与连线成员锚点共同使用缩放后的前置宽度，数字行、上点行和下点行还统一经过 `grace-member-slot` 的同一组“前置列 + 主音列”，不再各自手工偏移。

## 特殊连音

`tN[...]` 是局部音符组合语法。解析器不会把整组压成一个事件，而是将成员继续解析为普通音符、和弦或倚音，只在每个顶层事件上附加同一个 `tuplet.id`，并记录 `number`、`index` 和 `count`。因此既有的音符宽度、时值线、八度点、附点、变音记号及 notation link 均不需要为连音复制实现。

组后缀提供等时值简写，例如 `t3[1 2 3]/` 会先把 `/` 追加到三个成员，再调用原有事件解析器；成员时值不同时则直接写作 `t3[1/ 2// 3// 4/]`。两种模式由解析器强制互斥。当前模型只服务排版，不保存或校验 `N:M` 实际时值比例，也不要求事件数量等于显示数字；连音组不可跨小节，且暂不嵌套。

时值线分组把整个连音组视为不可拆分的视觉单元。普通音符累计到四分音符时会断开时值线，但连音组会延迟到组末尾再断开；例如 `t3[1 1 1]/` 的三枚音符保持一条连续时值线，并与组外的短音分组。

布局阶段从 `row-event-positions` 恢复每组首尾主音中心，用较浅的两段三次贝塞尔曲线绘制弧线，并在中央留下真实缺口放置斜体数字。若首尾事件是倚音组，端点复用倚音装饰弧线的目标搜索，落在被装饰的主音中心而不是倚音事件槽中心。只有实际位于弧线外侧的边界倚音（起点处的前倚音、终点处的后倚音）不计入垂直障碍；终点处的前倚音、起点处的后倚音以及内部倚音仍会抬高弧线。弧线范围不改变任何事件宽度；上方空间根据组内八度点、和弦和倚音的最高障碍局部避让。圆滑线或延音线也按横向范围局部避让：只有与当前连音组相交的连线才会把它抬高，同行其他连线不会影响其位置。

这样可以在不同字号下等比缩放，同时避免在 `layout()` 中混用 `em` 和 `pt` 比较。

## 小节与分行

输入中的 `|` 结束一个小节。分行只允许发生在小节之间。

解析完成后，最后一个小节会统一标记为终止小节，无论源码末尾是否显式写了 `|`。终止线使用独立的加宽槽位，在槽内绘制左细右粗两条竖线；粗线右外沿对齐普通小节线的右外沿，计算时包含普通线自身的半个笔画宽度，增加的双线宽度向左展开。整个槽宽仍计入最后一小节的最小宽度，使两端对齐与分行计算保持一致。

小节线高度只由主音数字行和固定的上下延伸决定。和弦叠放的高音、上下八度点、倚音及时值线均不参与小节线高度计算，因此同一行内普通小节线与含和弦小节的小节线保持等高。

每个小节的最小宽度为：

```text
sum(note.min-width) + bar-gap + bar-width
```

其中 `bar-gap + bar-width` 只在该小节带小节线时计入。

每一行用贪心策略放入尽可能多的小节：

```text
candidate-width = 当前行宽度 + min-measure-gap + 下一个小节宽度
```

如果候选行宽超过可用行宽，就在下一个小节前换行。若边界两侧存在跨小节的“倚音—主音”关系，则该边界禁止换行；必要时会把倚音所在小节一并移到下一行。若这两个小节自身已经超过行宽，则允许它们暂时形成一个超宽行，优先保证语义关系不断开。

首行缩进会参与分行计算。第一行实际可用宽度为：

```text
first-line-width = line-width - first-indent
```

默认缩进为 `24pt`。后续行仍使用完整 `line-width`。这样缩进不会只在视觉上移动内容，而是会真实减少第一行可排入的小节数量。

## 行内对齐

行内最小宽度包括：

```text
所有小节最小宽度 + 小节间最小间距
```

如果需要两端对齐，剩余宽度会先平均分配到两类间隙：

- 音符之间的间隙。
- 小节之间的间隙。

音符盒子的最小宽度不被拉伸，表示基本时值宽度；拉伸只发生在间隙上。

数字头、上下点和时值线端点都按音符盒中心对齐。也就是说，较长时值的数字不会贴在时值盒左端，而是位于自己的时值盒中心。这样在 `5// 6/ 7//` 这类组合中，`6` 会自然落在左右两个十六分音符之间。

小节之间的间距不作为独立空列直接插在两个小节之间，而是折入后一小节的前导宽度。渲染后一小节时，会把“前导宽度 + 小节线前间距”平均分到音符组左右两侧：

```text
side-gap = (leading-gap + bar-gap) / 2
```

这样后一小节的音符组会位于前一条小节线和本小节小节线之间的中心，而不是被整段小节间距推偏。

最后一行默认不两端对齐，除非传入 `justify-last: true`。

同一段简谱的相邻系统之间保留 `2em` 的最小净空。该值按简谱字号等比缩放；和弦、八度点、倚音、连线和不同结尾等实际占高仍会在最小净空之外继续撑开行高。

## 反复与不同结尾

大括号结构在音符解析前被识别，当前支持 `r{...}`、`rN{...}` 和位于反复块内的 `aN{...}`。结尾标签也可以写成列举形式 `a1,2,3{...}` 或范围形式 `a1-3{...}`。绘制前会将标签展开并重新分组：长度至少为三的连续段合并为范围，长度为二的连续段仍逐项列出；每个编号统一带点，输入逗号在排版时改为空格，因此 `a1,2,4,5,6` 显示为 `1. 2. 4.–6.`。解析结果仍然是扁平的小节数组；结构信息作为 `repeat-start`、`repeat-end`、`repeat-count`、`volta`、`volta-start`、`volta-end` 等边界元数据附着在相关小节上。这样分行、音符布局和连线不需要改为递归树结构。

`r` 与 `a` 的开闭大括号本身隐含小节边界。解析器在进入或离开结构时会结束当前小节，而紧邻大括号、没有任何音符内容的 `|` 被视为冗余分隔符并忽略。因此显式与省略结构旁小节线的输入会得到相同的小节数组，也不会因 `} |` 产生空小节。

从整段开头开始的反复不绘制开始反复线；位于普通音乐之后的开始反复线才作为首个小节的前缀占据真实宽度。结束反复线替换末小节的普通小节线。反复线与终止小节线共用同一套细线宽、粗线宽和两线净间隔；反复点与音符附点使用相同的视觉半径，反复线槽会额外扩宽，以容纳圆点和点线间距。相邻反复段共享边界时，会合并为左右带点、中央仅有两条粗线的双向反复线，不保留细线。三遍及以上且没有不同结尾时，在结束反复线上方用 `Libertinus Serif` 标出 `×N`。

不同结尾范围按小节元数据生成行级覆盖片段。每一行只绘制本行覆盖的横线：语义起点绘制左钩和衬线编号，非末结尾的语义终点绘制右钩，最后结尾只有在同时到达终止小节线时才闭合。人工换行产生的片段边界始终开放，也不会重复编号。

范围线共享整行的音符基线，但不再共享整行最高的绘制位置。每个范围片段只检查自己覆盖小节中的上八度点、和弦高度与倚音抬升量，再按局部最高障碍决定横线高度；因此范围外的高和弦不会把没有障碍的结尾一并抬高。

范围线不以音符组或小节盒边缘为锚点，而是读取小节线的实际笔画坐标。普通结尾起点落在前一小节线中心。两个结尾在同一行共享结束反复线时，前一结尾的右钩落在细线上，后一结尾的左钩从粗线右缘开始，从而在同一边界上保持清晰的先后关系；如果结尾切换恰逢换行，下一结尾已不在同一坐标，上一行的右钩便直接落在粗线右外缘。最后结尾在终止小节线闭合时，右钩同样落在终止粗线的右外缘。

连续反复边界允许分行。同一行内，相邻的结束与开始反复合并为中央两条粗线的双向反复线；如果分行恰好发生在该边界，上一行改画完整的结束反复线，下一行改画完整的开始反复线。倚音跨小节仍属于受保护边界，不能在其关联的两个小节之间断行。第一版不支持嵌套反复。

普通段落后的开始反复也允许位于下一行。开始反复与前一小节同处一行时，它自身替代边界上的普通小节线；若分行将二者分开，上一行末尾会恢复普通小节线，下一行行首则保留完整的开始反复线。

## 时值线

`/` 数量决定时值线层数：

```text
1/     1 条线
1//    2 条线
1///   3 条线
```

连续短音先按累计时值切成若干组，每组最多等于一个四分音符。八分音符通常每两个一组，十六分音符每四个一组，三十二分音符每八个一组；混合时值和附点时值则按实际累计值决定边界。达到一个四分音符后，即使下一音仍带时值线，也必须开始新组。

同一组内的同层时值线绘制为整条线，而不是按音符格、间隔格分段绘制。这样可以避免线段之间出现断缝或上下错位。

对于某一层 `level`：

1. 按音符时值累计生成不超过一个四分音符的基础组。
2. 在每个基础组内找到连续满足 `note.beams >= level` 的音符段。
3. 计算该段从第一个音符盒到最后一个音符盒的总宽度。
4. 将线左右端点限制在数字头附近，而不是音符盒子的完整边缘。

当前线端点使用 `beam-note-width = size * 0.7` 控制。

## 上点

`'` 数量表示高八度点：

```text
1'    一个上点
1''   两个上点
```

上点按“行”统一预留高度：

1. 计算当前行中最大的 `octave-up`。
2. 所有小节都预留同样高度的上点层。
3. 每个音符的上点在该层内底部对齐。

这样同一行里即使上点数量不同，数字基线也不会被推乱。

## 下点

`,` 数量表示低八度点：

```text
1,    一个下点
1,,   两个下点
```

下点不做整行统一对齐。它绑定到该音符自己的时值层：

- 无时值线：下点放在数字下方。
- 一条时值线：下点放在第一条线下方。
- 两条时值线：下点放在第二条线下方。
- 三条时值线：下点放在第三条线下方。

实现上，下点不是外层垂直 `stack` 的独立行，而是对应数字/时值线层的零高度覆盖层。这样下点不会把后续时值线推开。

因为零高度覆盖层本身不参与 Typst 的行高计算，小节外层需要按本小节最大的下点数量额外预留下方高度。这个预留只影响行距，不改变数字和时值线之间的相对位置。

## 圆点绘制

上下点都使用同一套圆点函数绘制：

```text
dot-radius = size * 0.075
dot-gap    = size * 0.12
```

多个点竖直排列。上下点共享同一个点阵高度计算函数，以保证点大小和点间距一致。

## 连奏线与延音线避让

连线先按默认弧高生成，再检查其覆盖范围内的每个音符。数字顶部、上八度点列和和弦顶部都视为障碍物。

倚音组仍然只是一个水平布局事件，但其每个成员会展开成独立的连线锚点。锚点横坐标来自缩小后的成员宽度、成员间距、整组居中位置以及向主音靠近的偏移；纵向端点则按完整倚音组的抬升和八度点高度计算。因此圆括号既能标记首尾成员，也能直接标记中间成员，而不会改变倚音组本身的占位宽度。

倚音成员盒宽、成员间距、整组占位和连线锚点共用同一套组宽公式。时值线以完整组宽为基础，只在两端合计减去一个固定成员间距；不能逐个忽略内部间距，否则成员越多，时值线相对数字组就会越来越短。

倚音组虽然拥有自己的数字、时值线和八度点高度，但在主旋律的数字行中必须作为覆盖层绘制。其布局盒高度只保留普通主音数字的高度，倚音本体向上移动且不参与该行测量；否则整个小节的主音行会被撑高，主旋律时值线和下八度点都会被错误地下推。

倚音本体底边与装饰弧线起点之间另留固定的相对间隙。弧线仍从原锚点起笔，只把倚音数字、时值线和八度点整体继续上移；这样低八度点不会与弧线线头粘连。该间隙同时计入行上方预留和倚音内部连线的垂直锚点。

倚音装饰弧线的目标按整行事件搜索，而不是限制在当前小节。整行先计算每个布局事件的中心横坐标，再把目标音符及中心距离切片传回各小节渲染。因此 `g[...] | 1` 和 `1 | g<[...]` 都能跨过小节线连接，同时不改变小节自身的宽度模型。

倚音圆点的半径和间距由 `note-head-width` 推导，绘制与布局补偿共同调用同一组函数。不能一边使用当前 `em` 绘制、一边使用音符宽度估算高度，否则误差会随八度点层数累积，最终让数字和时值线发生相对漂移。

倚音事件仍使用主音宽度的规范中心盒，但可见倚音组通常比该盒更宽。渲染时先测量完整倚音组，再以 `note-head-width / 2 - group-width / 2` 显式向左溢出；不能依赖 `align(center)` 自动处理宽子项，否则 Typst 会把溢出内容近似锚在首个成员附近，而成员连线坐标仍按整体中心计算，二者便会错位。

同一小节内，倚音不能只按固定距离向主音移动，因为四分、八分和十六分音符的时值盒宽不同。当前偏移由两者中心距离反推，使倚音组可见边缘到主音字形边缘保持固定间距；倚音成员连线锚点复用同一偏移。跨小节时则保留较小的固定偏移，避免倚音本体越过小节线。

检查时用音符中心在弧线中的相对横坐标近似贝塞尔参数，计算曲线经过该位置时的高度。如果曲线没有高于障碍物及固定安全距离，就反推出所需弧高，并将整条弧线统一抬高。最终弧高也会加入行的上方空间预留，避免抬高后的弧线碰到上一行。

跨行连线按片段分别避让。行末片段仍在最高点水平结束，行首片段从最高点水平开始。

连线不是等宽描边，而是由上下两条贝塞尔边界闭合成实心带状路径。弧线中部较粗，端点保留约一半宽度，并用半圆形贝塞尔端帽闭合，因此不会收成尖头。

跨行边界不属于音乐意义上的端点，因此不使用收细圆头：行末和行首都保持完整中部线宽，并以垂直平切边结束，使上下两行看起来仍是同一条连续带状曲线。

## 当前限制

- `-` 当前仍会参与音符事件布局，后续应单独解析为延音或占位事件。
- 多个 melody track 目前只是顺序渲染，没有对齐小节和系统。
- lyrics track 当前只解析类型，不参与布局。
- 附点、连音、装饰音等还没有完整语义。
