# 实现说明

本文记录当前 `jianpu.typ` 的核心实现方式，方便后续继续开发时理解现状。

## 模块结构

- `src/parser.typ`：raw 分词、音符属性和 score 数据模型。
- `src/geometry.typ`：由字号推导的全局私有尺寸。
- `src/glyphs.typ`：数字头、和弦、倚音、圆点及其他局部图元。
- `src/links.typ`：横向系统几何、连线锚点、跨行片段、曲线和避让。
- `src/layout.typ`：小节各绘制层、整行分配和 track 渲染。
- `jianpu.typ`：公开参数、输入解析和模块编排。

依赖保持单向：图元不依赖布局，连线只依赖图元，布局组合图元与连线，公开入口最后调用布局。各绘制层虽然都有列数组构造，但其单元内容、尾部宽度和覆盖层语义不同，目前只复用音符间距解析；继续强行合并会引入大量条件分支。

## 输入与 track

`jianpu` 接收一组或多组 raw 代码块：

```typst
#jianpu(
  ```melody
  1 2 3 4 | 5/ 6/ 7/ 1/ |
  ```,
)
```

raw 的语言标记用于区分 track 类型：

- `melody`：旋律，当前会渲染。
- `jianpu`：兼容旧写法，按旋律处理。
- `lyrics`：歌词，占位保留，当前不渲染。

内部先将 raw group 解析为 track，再组成 score：

```text
score
  tracks[]
    kind
    source
    measures[]
```

当前只渲染 `kind == "melody"` 的 track。多 track 目前是顺序渲染，尚未做跨 track 的 system-level 对齐。

## 音符解析

除 `|` 以外，每个 token 都会被解析为一个音符事件。当前 `0`、`X` 也算音符事件。

音符对象主要字段：

```text
note
  raw             原始 token
  beams           "/" 数量
  pitch           音级
  octave          八度偏移
  relative-pitch  相对音高，用于后续排序
  octave-up       "'" 数量
  octave-down     "," 数量
  dots            附点数量
  min-width       最小宽度
```

当前只显示 token 的第一个字符，后缀作为属性处理。`-` 例外：它仍可按当前模型参与音符事件布局，但显示时不使用字体默认减号，而是绘制一条居中的横线，避免默认字形过短、位置偏低。

## 最小宽度

音符最小宽度由时值决定：

```text
1      四分音符，2em
1/     八分音符，1.5em
1//    十六分音符，1em
1///   三十二分音符，1em
```

实际实现中这些值都由 `size` 推导为绝对长度：

```text
quarter-width = size * 2
eighth-width  = size * 1.5
short-width   = size
```

附点是音符属性，不直接混入数字字形。每个附点使音符最小宽度增加其原始时值宽度的一半：

```text
dotted-width = base-duration-width * (1 + dots * 0.5)
```

数字仍位于时值盒中心；附点根据数字实际字形宽度放在其右侧，使用固定的相对间距，并位于数字高度中心略偏下。因此改变时值只改变占位宽度，不会改变附点与数字之间的视觉距离。

这样可以在不同字号下等比缩放，同时避免在 `layout()` 中混用 `em` 和 `pt` 比较。

## 小节与分行

输入中的 `|` 结束一个小节。分行只允许发生在小节之间。

解析完成后，最后一个小节会统一标记为终止小节，无论源码末尾是否显式写了 `|`。终止线使用独立的加宽槽位，在槽内绘制左细右粗两条竖线；粗线右外沿对齐普通小节线的右外沿，计算时包含普通线自身的半个笔画宽度，增加的双线宽度向左展开。整个槽宽仍计入最后一小节的最小宽度，使两端对齐与分行计算保持一致。

小节线高度只由主音数字行和固定的上下延伸决定。和弦叠放的高音、上下八度点、倚音及时值线均不参与小节线高度计算，因此同一行内普通小节线与含和弦小节的小节线保持等高。

每个小节的最小宽度为：

```text
sum(note.min-width) + bar-gap + bar-width
```

其中 `bar-gap + bar-width` 只在该小节带小节线时计入。

每一行用贪心策略放入尽可能多的小节：

```text
candidate-width = 当前行宽度 + min-measure-gap + 下一个小节宽度
```

如果候选行宽超过可用行宽，就在下一个小节前换行。若边界两侧存在跨小节的“倚音—主音”关系，则该边界禁止换行；必要时会把倚音所在小节一并移到下一行。若这两个小节自身已经超过行宽，则允许它们暂时形成一个超宽行，优先保证语义关系不断开。

首行缩进会参与分行计算。第一行实际可用宽度为：

```text
first-line-width = line-width - first-indent
```

默认缩进为 `24pt`。后续行仍使用完整 `line-width`。这样缩进不会只在视觉上移动内容，而是会真实减少第一行可排入的小节数量。

## 行内对齐

行内最小宽度包括：

```text
所有小节最小宽度 + 小节间最小间距
```

如果需要两端对齐，剩余宽度会先平均分配到两类间隙：

- 音符之间的间隙。
- 小节之间的间隙。

音符盒子的最小宽度不被拉伸，表示基本时值宽度；拉伸只发生在间隙上。

数字头、上下点和时值线端点都按音符盒中心对齐。也就是说，较长时值的数字不会贴在时值盒左端，而是位于自己的时值盒中心。这样在 `5// 6/ 7//` 这类组合中，`6` 会自然落在左右两个十六分音符之间。

小节之间的间距不作为独立空列直接插在两个小节之间，而是折入后一小节的前导宽度。渲染后一小节时，会把“前导宽度 + 小节线前间距”平均分到音符组左右两侧：

```text
side-gap = (leading-gap + bar-gap) / 2
```

这样后一小节的音符组会位于前一条小节线和本小节小节线之间的中心，而不是被整段小节间距推偏。

最后一行默认不两端对齐，除非传入 `justify-last: true`。

## 时值线

`/` 数量决定时值线层数：

```text
1/     1 条线
1//    2 条线
1///   3 条线
```

连续短音先按累计时值切成若干组，每组最多等于一个四分音符。八分音符通常每两个一组，十六分音符每四个一组，三十二分音符每八个一组；混合时值和附点时值则按实际累计值决定边界。达到一个四分音符后，即使下一音仍带时值线，也必须开始新组。

同一组内的同层时值线绘制为整条线，而不是按音符格、间隔格分段绘制。这样可以避免线段之间出现断缝或上下错位。

对于某一层 `level`：

1. 按音符时值累计生成不超过一个四分音符的基础组。
2. 在每个基础组内找到连续满足 `note.beams >= level` 的音符段。
3. 计算该段从第一个音符盒到最后一个音符盒的总宽度。
4. 将线左右端点限制在数字头附近，而不是音符盒子的完整边缘。

当前线端点使用 `beam-note-width = size * 0.7` 控制。

## 上点

`'` 数量表示高八度点：

```text
1'    一个上点
1''   两个上点
```

上点按“行”统一预留高度：

1. 计算当前行中最大的 `octave-up`。
2. 所有小节都预留同样高度的上点层。
3. 每个音符的上点在该层内底部对齐。

这样同一行里即使上点数量不同，数字基线也不会被推乱。

## 下点

`,` 数量表示低八度点：

```text
1,    一个下点
1,,   两个下点
```

下点不做整行统一对齐。它绑定到该音符自己的时值层：

- 无时值线：下点放在数字下方。
- 一条时值线：下点放在第一条线下方。
- 两条时值线：下点放在第二条线下方。
- 三条时值线：下点放在第三条线下方。

实现上，下点不是外层垂直 `stack` 的独立行，而是对应数字/时值线层的零高度覆盖层。这样下点不会把后续时值线推开。

因为零高度覆盖层本身不参与 Typst 的行高计算，小节外层需要按本小节最大的下点数量额外预留下方高度。这个预留只影响行距，不改变数字和时值线之间的相对位置。

## 圆点绘制

上下点都使用同一套圆点函数绘制：

```text
dot-radius = size * 0.075
dot-gap    = size * 0.12
```

多个点竖直排列。上下点共享同一个点阵高度计算函数，以保证点大小和点间距一致。

## 连奏线与延音线避让

连线先按默认弧高生成，再检查其覆盖范围内的每个音符。数字顶部、上八度点列和和弦顶部都视为障碍物。

倚音组仍然只是一个水平布局事件，但其每个成员会展开成独立的连线锚点。锚点横坐标来自缩小后的成员宽度、成员间距、整组居中位置以及向主音靠近的偏移；纵向端点则按完整倚音组的抬升和八度点高度计算。因此圆括号既能标记首尾成员，也能直接标记中间成员，而不会改变倚音组本身的占位宽度。

倚音成员盒宽、成员间距、整组占位和连线锚点共用同一套组宽公式。时值线以完整组宽为基础，只在两端合计减去一个固定成员间距；不能逐个忽略内部间距，否则成员越多，时值线相对数字组就会越来越短。

倚音组虽然拥有自己的数字、时值线和八度点高度，但在主旋律的数字行中必须作为覆盖层绘制。其布局盒高度只保留普通主音数字的高度，倚音本体向上移动且不参与该行测量；否则整个小节的主音行会被撑高，主旋律时值线和下八度点都会被错误地下推。

倚音本体底边与装饰弧线起点之间另留固定的相对间隙。弧线仍从原锚点起笔，只把倚音数字、时值线和八度点整体继续上移；这样低八度点不会与弧线线头粘连。该间隙同时计入行上方预留和倚音内部连线的垂直锚点。

倚音装饰弧线的目标按整行事件搜索，而不是限制在当前小节。整行先计算每个布局事件的中心横坐标，再把目标音符及中心距离切片传回各小节渲染。因此 `g[...] | 1` 和 `1 | g<[...]` 都能跨过小节线连接，同时不改变小节自身的宽度模型。

同一小节内，倚音不能只按固定距离向主音移动，因为四分、八分和十六分音符的时值盒宽不同。当前偏移由两者中心距离反推，使倚音组可见边缘到主音字形边缘保持固定间距；倚音成员连线锚点复用同一偏移。跨小节时则保留较小的固定偏移，避免倚音本体越过小节线。

检查时用音符中心在弧线中的相对横坐标近似贝塞尔参数，计算曲线经过该位置时的高度。如果曲线没有高于障碍物及固定安全距离，就反推出所需弧高，并将整条弧线统一抬高。最终弧高也会加入行的上方空间预留，避免抬高后的弧线碰到上一行。

跨行连线按片段分别避让。行末片段仍在最高点水平结束，行首片段从最高点水平开始。

连线不是等宽描边，而是由上下两条贝塞尔边界闭合成实心带状路径。弧线中部较粗，端点保留约一半宽度，并用半圆形贝塞尔端帽闭合，因此不会收成尖头。

跨行边界不属于音乐意义上的端点，因此不使用收细圆头：行末和行首都保持完整中部线宽，并以垂直平切边结束，使上下两行看起来仍是同一条连续带状曲线。

## 当前限制

- `-` 当前仍会参与音符事件布局，后续应单独解析为延音或占位事件。
- 多个 melody track 目前只是顺序渲染，没有对齐小节和系统。
- lyrics track 当前只解析类型，不参与布局。
- 附点、连音、装饰音等还没有完整语义。
